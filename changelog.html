Latest · on main

Automations, sign-in and HTTPS

  • 19 automations in the same catalog as the reports, in four solution packs. Audit first, Enforce on explicit confirmation, per-run change limit, before/after snapshots and one-click rollback.
  • Separate write-capable Entra app for automations; the reporting app stays read-only.
  • Username + password sign-in on every page and API route (argon2id, lockout after 5 failures, 12-hour sessions).
  • HTTPS inside the container with a self-signed certificate it renews, or your own.
  • Group.ReadWrite.All is now opt-in. The reporting app asks for read permissions plus Mail.Send.
  • No silent failures: undeliverable jobs are saved paused, interrupted runs are never re-sent, failure alerts go out once per streak.
  • One shared report template with a visual composer and "Preview as" any report; reports, automations and templates share one plugin contract.

Unreleased (on main)

Security

  • Username + password sign-in — every page and API route requires signing in. The first visit creates the admin account (open for 30 minutes after start); passwords are argon2id hashes; 5 failures lock a username for 15 minutes; Settings → Account changes the password; bun run auth:reset-password <user> recovers access from the host. Sessions last 12 hours. Scripts/CI can use a machine key as Authorization: Bearer. Anonymous /api/health returns only status. ARGUS_AUTH_MODE=off disables the gate.
  • HTTPS inside the container — the image serves HTTPS on port 8100 with a self-signed certificate it generates on first boot (private key encrypted with ARGUS_MASTER_KEY, renewed before expiry), or your own via ARGUS_TLS_CERT_FILE/ARGUS_TLS_KEY_FILE. Next.js listens on loopback only; ARGUS_TLS=off restores plain HTTP.

  • Compose bind — ARGUS_BIND (default 0.0.0.0) chooses the host interface; 127.0.0.1 keeps Argus on the local machine.

  • Least-privilege Graph permissions (H2) — permissions are split into read reports, send email, and an opt-in "Manage Entra groups" (Group.ReadWrite.All, off by default). Quick Setup and standard groups stay local unless opted in; Entra group writes are refused otherwise. Executor, test-send and Test Connection share one effective sender. New GET/PUT /api/integrations/microsoft365/capabilities and a Settings panel explain each capability before consent.

  • One run contract (H3) — Run Now and scheduled runs share one delivery preflight (deliveryPreflight(): verified Mail.Send + effective sender), so the same job sends or is blocked the same way. Run Now on a paused job is a diagnostic run that never emails. Executions record trigger (scheduled/manual) and deliveryStatus (not_attempted/accepted/failed/unknown — "accepted" is not proof of receipt).

  • No silently undeliverable jobs (H4) — catalog quick-enable, starter pack, clone and the job editor share activationDecision(): a job that would email no one is saved paused with a "Fix it" link. Jobs can be explicitly compute-only (deliveryMode: "none").

  • Restart safety (H5) — runs left unfinished by a stopped process are marked interrupted with delivery unknown at boot and never re-sent automatically; skipped scheduled fires (overlap, snooze) are recorded in the audit trail instead of only the console. The container boots the scheduler itself, without waiting for a health probe.

  • Failure-alert incidents (H7) — one incident per failure streak (new alert_incidents table): admins are emailed once when the streak reaches the threshold, a failed alert send is recorded and retried with backoff (5 min → 6 h), a new streak within 1 hour of the last alert is recorded but not emailed, and the incident closes when the job recovers. GET /api/alerts/incidents lists them.

Automations (merged from feat/automations)

  • Automations in the same app — the automation engine (audit/enforce, per-run change limit, before/after snapshots, rollback) now shares Argus's sender, send check, templates, audit trail and restart handling. New policies and packs start in audit; enforce needs a finished audit of the current settings plus explicit confirmation, and is recorded with the signed-in user. Changing an enforcing policy's settings returns it to audit. Automation emails use an editable, versioned "Automation run template".
  • One plugin contract for reports, automations and templates — new src/services/automations/contract.ts, tests/automation-contract.test.ts and tests/template-contract.test.ts run in the CI plugins job and in plugin:validate. bun run plugin:new <id> --kind=automation scaffolds an automation that passes the contract. The argus-plugin agent skill (.claude/skills/argus-plugin/) documents how to build each kind.
  • expired-app-secret-hygiene is now medium risk (it deletes secrets with Application.ReadWrite.All).

Added

  • Reports and automations in one place — the Dashboard lists automation policies next to report jobs with a type tag ("Report" / "Automation · Audit|Enforce"), the same State and Last run columns (automation outcomes read Success, Drift found, Warning, Failed, Halted, Interrupted), a type filter, and overview counters that count both with the split shown. The Logs page shows report and automation logs together with a source filter, a type tag per line and links to the execution or run. GET /api/logs takes source=all|report|automation (default all) and runId; entries carry source, runId and href, with the same keyset paging and real totals across both sources. New run page /automations/runs/<id> shows the summary, each target's before/after state, and the run's logs.
  • Automations workspace (/automations) — a catalog of 19 Microsoft 365 automations managed like the report catalog: Policies / Catalog / Runs tabs, solution packs, per-policy schedule, notify rules and maxActionsPerRun circuit breaker. Every policy starts in Audit (read-only what-if; plan() runs behind a guard that rejects POST/PATCH/DELETE) and moves to Enforce explicitly. Each change stores before/after JSON snapshots and a rollback payload; runs expand to show them with one-click Roll back.
  • Isolated microsoft365-automation integration — separate read-write Entra app with its own auto_* vault keys, token cache, Graph transport and one-click provisioner; required scopes are derived from the automations' requiredPermissions.

  • One-click group provisioning for automation parameters (POST /api/automations/provision) — "Create group" creates or reuses the catalog-named Argus - … security group and fills its id (Unsupported OS group, Break-Glass groups). Adds Group.Create to the automation app scopes.
