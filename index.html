The all-seeing eye for your Microsoft 365 tenant.

Argus runs scheduled Microsoft Graph reports (sign-in failures, inactive guests, expiring app secrets, license waste and more) and emails your team when your rules match. When a report finds a problem, Argus automations can fix it: Audit first, Enforce when you say so, roll back if needed. One Docker container on your own infrastructure.

How reports work

Five stages, every run

Argus follows a Jenkins-style model: Catalog → Jobs → Executions → Logs. Each scheduled run goes through the same pipeline.

  1. 1

    Fetch

    Pull data from Microsoft Graph with pagination, $select and retry with back-off.

  2. 2

    Analyze

    Compare against previous runs; flag counts more than 2σ from the baseline.

  3. 3

    Decide

    Apply your rule: always, count above a threshold, count changed, anomaly, new rows, or a metric moving by a set amount. Maintenance windows mute runs.

  4. 4

    Render

    Fill an editable HTML or plain-text email template.

  5. 5

    Deliver

    Send through Microsoft Graph from your configured mailbox, or call a webhook when a run is suppressed. Every run and log line is stored.

Automations New

Find it, then fix it, with guardrails

19 built-in automations act on what the reports find. They run through a separate, write-capable Entra app, so the reporting app never changes your tenant.

  1. 1

    Audit

    Every new policy starts here. A read-only what-if: the engine rejects any write, and the run lists exactly what would change.

  2. 2

    Enforce

    Only after a finished audit of the current settings and an explicit confirmation. Max changes per run halts a run that would change too much.

  3. 3

    Roll back

    Each change stores its before and after state. Reversible changes undo in one click; the few that can't (Intune retire, expired-secret removal) are marked.

Features

Built for the admin who owns the tenant

One catalog

26 read-only reports (identity, security, infrastructure, usage, plus a custom Graph query) next to the automations, with solution packs and maturity labels.

Send when the rule matches

Thresholds, changes, anomalies, new items and metric deltas decide whether a run emails anyone. Maintenance windows mute runs.

Row-level history and diff

Each run snapshots its rows, so "new items" means new identities, not just a bigger count. Per-job trend charts included.

No silent failures

Jobs that would email no one are saved paused. Interrupted runs are never re-sent. Failure alerts go out once per streak, not once per run.

Template studio

One shared template for every report: visual composer or highlighted HTML, live preview as any report, version history.

Guided Microsoft 365 setup

Device Code sign-in registers the Entra ID app with a local RSA-2048 certificate. Recipients can be Entra ID security groups or local lists.

Security

Your tenant, your host, your keys

  • Sign-in on every page.

    Every page and API route needs a signed-in user, except the sign-in page and a status-only health check. The admin account is created on first visit (open for 30 minutes after start); passwords are argon2id hashes, five failures lock a username for 15 minutes, and sessions last 12 hours.

  • HTTPS in the container.

    The image serves HTTPS on port 8100 with a self-signed certificate it generates and renews, or your own certificate. The app itself listens only on loopback inside the container.

  • Read-only reports, separate write app.

    Reports use app-only Graph access with a local X.509 certificate (RS256 client assertion) or a client secret. Automations use their own Entra app, so write rights stay out of the reporting path.

  • Encrypted vault, one secret.

    Credentials are stored AES-256-GCM encrypted in SQLite. ARGUS_MASTER_KEY is the only required variable; the installer writes it to .env, so back it up and restrict access.

  • Hardened container, known destinations.

    Non-root with no-new-privileges, telemetry off. Outbound traffic goes to Entra ID and Graph, Exchange Online for automatic mailbox setup, and webhooks you configure.

Know what you consent to

Reporting app: 15 read permissions plus Mail.Send to deliver reports. Group.ReadWrite.All is opt-in ("Manage Entra groups", off by default).

Automation app: write-capable, and only if you connect it. Its permissions are built from the automations you choose (all automations, or active policies only). With all of them it includes rights such as User.ReadWrite.All, Policy.ReadWrite.ConditionalAccess and RoleManagement.ReadWrite.Directory.

Quick Setup's one-time Device Code sign-in uses the signed-in admin's own delegated rights to create these apps. Use Advanced setup to grant permissions yourself.

Requirements

What you need

  • A Microsoft 365 tenant and an admin who can consent to an Entra ID app.
  • Docker (or Bun 1.3+ to run from source).
  • An Exchange Online mailbox to send from.
  • For automations: a second, write-capable Entra app. Quick Setup can create it.
  • Entra ID P1 for sign-in-based reports, P2 for risk reports, Intune for device compliance. Usage and license reports work on standard Microsoft 365 plans.

Quick start

Running in about a minute

Clone and install with Docker
git clone https://github.com/RohiRIK/argus.git
cd argus
./install.sh docker

Generates ARGUS_MASTER_KEY into .env, builds the image and serves on https://localhost:8100.

Or run the published image
# generate a key once and keep it safe
export ARGUS_MASTER_KEY=$(openssl rand -hex 32)
docker run -d --name argus -p 8100:8100 \
  -e ARGUS_MASTER_KEY \
  -v argus-data:/app/data \
  ghcr.io/rohirik/argus:latest

FAQ

Questions admins ask

Is Argus a SaaS?

No. You run it yourself. The UI, scheduler, SQLite database and worker live in one container on your infrastructure, behind its own sign-in.

What does it cost?

Nothing. Argus is MIT licensed. Some reports need Microsoft licences (Entra ID P1/P2, Intune) for the underlying data.

Can Argus change my tenant?

Reports never do. Changes come only from automations you set up, through a separate write-capable app. Every policy starts in Audit, Enforce needs an explicit confirmation, and reversible changes can be rolled back.

What permissions does it ask for?

The reporting app asks for 15 read permissions plus Mail.Send; Group.ReadWrite.All is opt-in. The automation app asks only for what your chosen automations need. Both lists are in the Security section.

Does it email on every run?

Only if you want it to. Each job has a rule (always, threshold, change, anomaly, new items or metric delta), and maintenance windows mute runs.

Where is my data stored?

In a SQLite database in the container's data volume. Integration credentials are encrypted with AES-256-GCM; report data stays on your host apart from the emails and webhooks you configure.

Can I monitor several tenants?

One Argus instance connects to one tenant. Run one instance per tenant.

Can I write my own reports or automations?

Yes. Use the Custom Graph Query report, or scaffold a plugin with bun run plugin:new <id> --kind=automation. Reports, automations and templates share one plugin contract that CI validates.
