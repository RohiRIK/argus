How it works

Five stages, every run

Argus follows a Jenkins-style model: Catalog → Jobs → Executions → Logs. Each scheduled run goes through the same pipeline.

  1. 1

    Fetch

    Pull data from Microsoft Graph with pagination, $select and retry with back-off.

  2. 2

    Analyze

    Compare against previous runs; flag counts more than 2σ from the baseline.

  3. 3

    Decide

    Apply your rule: always, count above a threshold, count changed, anomaly, new rows, or a metric moving by a set amount. Maintenance windows mute runs.

  4. 4

    Render

    Fill an editable HTML or plain-text email template.

  5. 5

    Deliver

    Send through Microsoft Graph from your configured mailbox, or call a webhook when a run is suppressed. Every run and log line is stored.

Features

Built for the admin who owns the tenant

25 reports + custom Graph query

Identity, security, infrastructure and usage reports, plus your own Graph GET query. Maturity is labelled per report.

Send when the rule matches

Thresholds, changes, anomalies, new items and metric deltas decide whether a run emails anyone.

Row-level history and diff

Each run snapshots its rows, so "new items" means new identities, not just a bigger count. Per-job trend charts included.

Guided Microsoft 365 setup

Quick Setup uses Device Code sign-in to register the Entra ID app and generate a local RSA-2048 certificate. Advanced setup lets you do it by hand.

Recipients from Entra ID groups

Point a job at an Entra security group; members are resolved at send time.

Editable templates

HTML and plain-text templates with variable chips, sandboxed preview and version history.

Security

Your tenant, your host, your keys

  • App-only Graph access.

    Scheduled runs authenticate as an Entra ID application with a locally generated X.509 certificate (RS256 client assertion) or a client secret. No user session is needed.

  • Encrypted credential vault.

    Tenant, app, certificate key and mailbox settings are stored AES-256-GCM encrypted in SQLite, each value with its own IV and auth tag.

  • One secret to protect.

    ARGUS_MASTER_KEY is the only required environment variable. The installer writes it to .env: back it up and restrict access, because losing it makes stored credentials unrecoverable.

  • Hardened container.

    Runs as a non-root user with no-new-privileges. Next.js telemetry is disabled; Argus sends nothing to its author.

  • Where data goes.

    Outbound traffic goes to Microsoft Entra ID and Graph, to Exchange Online when you use automatic mailbox setup, and to webhooks you configure. Nothing else.

Know what you consent to

Quick Setup asks an administrator to approve the catalog's read permissions plus two non-read permissions: Group.ReadWrite.All (to manage recipient groups) and Mail.Send (to deliver reports). That consent is broader than the reports you choose to run. To create the app registration, the one-time Device Code sign-in also uses the signed-in admin's own delegated rights (application, role and group management).

Use Advanced setup to review and grant permissions yourself. Argus has no built-in sign-in yet: keep the web UI on a trusted network or behind your own access proxy.

Requirements

What you need

  • A Microsoft 365 tenant and an admin who can consent to an Entra ID app.
  • Docker (or Bun 1.3+ to run from source).
  • An Exchange Online mailbox to send from.
  • Entra ID P1 for sign-in-based reports, P2 for risk reports, Intune for device compliance. Usage and license reports work on standard Microsoft 365 plans.

Quick start

Running in about a minute

Clone and install with Docker
git clone https://github.com/RohiRIK/argus.git
cd argus
./install.sh docker

Generates ARGUS_MASTER_KEY into .env, then serves on http://localhost:8100.

Or run the published image
# generate a key once and keep it safe
export ARGUS_MASTER_KEY=$(openssl rand -hex 32)
docker run -d --name argus -p 8100:8100 \
  -e ARGUS_MASTER_KEY \
  -v argus-data:/app/data \
  ghcr.io/rohirik/argus:latest

FAQ

Questions admins ask

Is Argus a SaaS?

No. You run it yourself. The UI, scheduler, SQLite database and worker live in one container on your infrastructure.

What does it cost?

Nothing. Argus is MIT licensed. Some reports need Microsoft licences (Entra ID P1/P2, Intune) for the underlying data.

What permissions does it ask for?

15 read permissions for the report catalog, plus Group.ReadWrite.All for recipient groups and Mail.Send for delivery. The full list is in the Security section, and Advanced setup lets you grant them yourself.

Does it email on every run?

Only if you want it to. Each job has a rule (always, threshold, change, anomaly, new items or metric delta), and maintenance windows mute runs.

Where is my data stored?

In a SQLite database in the container's data volume. Integration credentials are encrypted with AES-256-GCM; report data stays on your host apart from the emails and webhooks you configure.

Can I monitor several tenants?

One Argus instance connects to one tenant. Run one instance per tenant.

Can I write my own reports?

Yes. Use the Custom Graph Query report, or add a report plugin (see the repository).
